> 版本：v1.0 | 更新：2026-04-01 | 状态：草稿

## 1. 设计目标

### 1.1 核心诉求

| 诉求 | 描述 | 优先级 |
|------|------|--------|
| 信息不遗漏 | 每天海量科技资讯，AI 自动抓取、筛选、去重 | P0 |
| 时效性保障 | 热点发布黄金窗口内容第一时间生成初稿 | P0 |
| 质量稳定 | AI 初稿经过事实核查、敏感词过滤后发布 | P1 |
| 多平台适配 | 同一内容自动适配微信、知乎、头条不同格式 | P1 |
| 风格一致性 | 学习博主历史文章风格，保持人设一致 | P2 |

### 1.2 设计原则

- **AI 是副驾驶，人类是机长** — AI 负责信息处理和初稿生成，最终决策在人类
- **模块化可插拔** — 每个 Agent 独立开发测试，通过标准接口通信
- **数据驱动** — 一切皆可量化：热度评分、质量评分、发布效果追踪
- **本地优先** — 数据存储在本地，API Key 由用户自持

## 3. Agent 详细设计

### 3.1 Collector Agent（信息收集 Agent）

**职责：** 从各信息源抓取原始内容，去重、分类、初步评估

**输入：** 信息源配置（RSS 列表、GitHub 查询条件等）

**输出：** 结构化的原始内容条目集合

**信息源分类：**

| 类型 | 来源 | 抓取频率 | 数据量/天 |
|------|------|---------|-----------|
| 科技新闻 | 36氪、爱范儿、品玩等 RSS | 每30分钟 | ~200条 |
| 技术社区 | GitHub Trending、Hacker News | 每小时 | ~100条 |
| 学术前沿 | arXiv CS.AI、 PapersWithCode | 每2小时 | ~50条 |
| 公司动态 | OpenAI/Google AI Blog | 每小时 | ~10条 |
| 社交媒体 | 微博热搜、知乎热榜 | 每15分钟 | ~50条 |

**技术实现：**
- RSS 抓取：`feedparser` 库
- GitHub：`gh api` 或 PyGithub
- 网页内容：`Jina Reader`（`https://r.jina.ai/`）去除广告和干扰元素
- 并发控制：asyncio + aiohttp，单源并发不超过 5 请求/秒

**去重策略：**
- URL 去重（exact match）
- Title 相似度去重（TF-IDF + 阈值 0.85）
- 时间窗口去重（同一事件 24 小时内只保留最新来源）

---

### 3.2 Curator Agent（选题筛选 Agent）

**职责：** 对收集的原始内容进行评分和排序，输出每日选题推荐清单

**输入：** Collector Agent 输出的结构化内容列表

**输出：** 带评分的选题推荐列表（TOP 10）

**评分模型：**

```
综合得分 = 热度得分 × 0.4 + 受众匹配度 × 0.3 + 时效性 × 0.2 + 原创空间 × 0.1
```

| 维度 | 计算方式 | 权重 |
|------|---------|------|
| 热度得分 | 社交媒体讨论量 × 0.5 + 新闻源覆盖度 × 0.5 | 40% |
| 受众匹配度 | 基于博主历史选题的 cosine similarity | 30% |
| 时效性 | 事件发生到现在的小时数衰减（指数衰减，半衰期6小时） | 20% |
| 原创空间 | Google 搜索结果中相似内容数量（越少越高） | 10% |

**输出格式：**

```json
{
  "topic": "Claude 3.7 发布：编程能力大幅提升",
  "source_url": "https://anthropic.com/news/claude-3-7",
  "source_name": "Anthropic Blog",
  "published_at": "2026-04-01T08:00:00Z",
  "score": 92.5,
  "breakdown": {
    "hot_score": 95,
    "audience_match": 88,
    "timeliness": 90,
    "originality": 85
  },
  "suggested_angle": "与 GPT-4 编程能力对比测试",
  "suggested_type": "产品速递",
  "key_points": ["关键点1", "关键点2"],
  "related_articles": ["相关链接列表"]
}
```

### 3.3 Writer Agent（内容创作 Agent）

**职责：** 基于选题信息，生成符合博主风格的完整文章初稿

**输入：** Curator Agent 输出的选题详情

**输出：** 结构化的文章内容（含标题、导语、正文、小标题、配图建议）

**工作流程：**

```
选题输入
    │
    ▼
Step 1: 资料深度消化
    - 抓取所有相关链接的全文内容
    - 提取关键数据、观点、引用
    - 识别争议点和讨论空间
    │
    ▼
Step 2: 文章结构规划
    - 确定文章类型（速递/深度/观点/评测）
    - 设计叙事逻辑（STAR 法则：情境→任务→行动→结果）
    - 规划小标题（3-5 个）
    │
    ▼
Step 3: 风格适配
    - 加载博主历史文章风格配置
    - 匹配语气（亲切/专业/犀利）
    - 匹配段落长度和格式偏好
    │
    ▼
Step 4: 内容生成
    - 生成 3 个候选标题（各自附上理由）
    - 写导语（黄金3秒原则）
    - 写正文各段落
    - 生成结语和 CTA
    │
    ▼
Step 5: 排版优化
    - Markdown 格式转微信公众号 HTML
    - 插入配图建议和位置
    - 高亮重点语句
    - 添加阅读时长预估
```

**Prompt 模板策略：**
- 系统 Prompt：注入博主风格配置
- 用户 Prompt：包含文章类型、正文要点、字数要求

**输出格式：**

```json
{
  "title_candidates": [
    {"title": "标题1", "reason": "理由"},
    {"title": "标题2", "reason": "理由"},
    {"title": "标题3", "reason": "理由"}
  ],
  "selected_title": "标题2",
  "lead": "导语内容...",
  "body": {
    "section_1": {
      "heading": "小标题1",
      "content": "段落内容...",
      "image_suggestion": "配图建议"
    }
  },
  "conclusion": "结语...",
  "cta": "行动号召...",
  "reading_time_minutes": 8,
  "word_count": 2000,
  "tags": ["AI", "Claude", "编程"]
}
```

### 3.4 Reviewer Agent（质量把控 Agent）

**职责：** 对 Writer Agent 输出的初稿进行多维度审核

**审核维度：**

| 维度 | 检查内容 | 处理方式 |
|------|---------|---------|
| 事实核查 | 数据准确性、引用可靠性 | 标记可疑内容，人工复核 |
| 敏感词过滤 | 政治敏感、色情暴力、品牌风险词 | 自动替换或删除 |
| 原创检测 | 与网上现有内容的相似度 | 相似度 > 60% 段落标记重写 |
| 逻辑审查 | 段落衔接、论证完整性 | 标记逻辑断层 |
| 标题优化 | 是否吸引点击、是否符合平台规范 | 生成优化建议 |
| 合规审查 | 微信公众号发标规范、品牌词使用 | 返回修改清单 |

**输出格式：**

```json
{
  "overall_pass": false,
  "issues": [
    {
      "type": "fact_check",
      "severity": "high",
      "location": "正文第3段",
      "content": "提及的 GPT-4 编程得分与官方数据不符",
      "suggestion": "核实后更正为 85.3%"
    },
    {
      "type": "sensitive_word",
      "severity": "medium",
      "location": "标题",
      "content": "包含可能引起争议的表述",
      "suggestion": "建议换用中性措辞"
    }
  ],
  "quality_score": 78,
  "readability_score": 85,
  "recommendation": "建议人工审核后发布"
}
```

### 3.5 Publisher Agent（发布分发 Agent）

**职责：** 将审核通过的最终稿件适配并发布到各平台

**支持的平台：**

| 平台 | 支持功能 | 发布方式 |
|------|---------|---------|
| 微信公众号 | 发布图文消息 | 官方 API |
| 知乎专栏 | 发布文章 | 知乎 API（需认证） |
| 今日头条 | 发布文章 | 头条号 API |
| 微博 | 发布动态 | 微博 API（需 Cookie） |
| 自定义 Webhook | 推送 Markdown | HTTP POST |

**多平台适配策略：**
- 建立平台格式转换层，统一内部表示 → 各平台格式
- 微信：Markdown → HTML（公众号格式）
- 知乎：保持 Markdown，增加代码块
- 头条：适配头条推荐算法关键词

## 4. 数据模型

### 4.1 核心实体

```
Article（文章）
  ├── id: UUID
  ├── topic_id: FK → Topic
  ├── title: str
  ├── content: Text（Markdown）
  ├── html_content: Text（微信公众号格式）
  ├── status: Enum（draft/reviewing/approved/published/rejected）
  ├── author_id: FK → Author
  ├── quality_score: float
  ├── published_at: datetime
  ├── created_at: datetime
  └── updated_at: datetime

Topic（选题）
  ├── id: UUID
  ├── title: str
  ├── source_url: str
  ├── source_name: str
  ├── score: float
  ├── breakdown: JSON
  ├── suggested_angle: str
  ├── suggested_type: Enum（quick_news/deep_analysis/review/opinion）
  ├── status: Enum（pending/scored/approved/rejected/used）
  ├── rejection_reason: str（可选）
  ├── created_at: datetime
  └── used_at: datetime（选题被文章使用时记录）

Author（博主）
  ├── id: UUID
  ├── name: str
  ├── style_config: JSON
  │   ├── tone: str（亲切/专业/犀利）
  │   ├── avg_word_count: int
  │   ├── preferred_structure: str
  │   └── banned_words: list[str]
  └── platforms: JSON（各平台配置）

RawContent（原始内容）
  ├── id: UUID
  ├── url: str（唯一索引）
  ├── title: str
  ├── content: Text
  ├── source_name: str
  ├── source_type: Enum（rss/github/news/social）
  ├── published_at: datetime
  ├── fetched_at: datetime
  ├── is_duplicate: bool
  └── embedding: Vector（用于相似度计算）
```

### 4.2 向量知识库设计

**用途：**
- 文章内容相似度检测（避免重复选题）
- 博主风格向量学习
- 读者兴趣画像分析

**向量维度：** 1536（OpenAI text-embedding-3-small）

## 5. API 设计

| 方法 | 路径 | 描述 |

## 6. 调度策略

### 6.1 定时任务

| 任务 | 调度频率 | 说明 |
|------|---------|------|
| 收集信息 | 每30分钟 | 全量信息源抓取 |
| 选题评分 | 每小时 | 对新收集内容评分 |
| 选题推荐 | 每天 08:00 | 生成当日选题清单并推送 |
| 文章生成 | 人工触发 | 选定题后开始写作 |
| 数据清理 | 每天 03:00 | 删除7天前原始数据（保留向量） |
| 效果追踪 | 每周一 | 汇总上周发布效果数据 |

### 6.2 Celery 任务队列

```
queues:
  - collect（高优先级）
  - score（中优先级）
  - write（低优先级）
  - publish（低优先级）
```

## 7. 安全设计

### 7.1 认证授权

- API Key 认证（用于外部系统集成）
- OAuth 2.0（用于微信公众号等平台授权）
- Cookie 加密存储（AES-256）

### 7.2 数据安全

- 本地存储优先，敏感数据不外传
- API Key 通过环境变量注入，不写入代码库
- 用户数据与示例数据严格分离

### 7.3 发布安全

- 所有发布操作需要二次确认
- 发布前自动生成预览
- 发布记录完整审计
