## 2. 信息收集模块（Collector）

### 2.1 RSS 订阅抓取

**功能描述：** 定时抓取配置的 RSS 订阅源，返回结构化内容条目。

**信息源配置（sources.yaml）：**

```yaml
rss_sources:
  - name: "36氪"
    url: "https://www.36kr.com/feed"
    category: "news"
    fetch_interval_minutes: 30

  - name: "爱范儿"
    url: "https://www.ifanr.com/feed"
    category: "news"
    fetch_interval_minutes: 30

  - name: "品玩"
    url: "https://www.pingwest.com/feed"
    category: "news"
    fetch_interval_minutes: 30

  - name: "Hacker News"
    url: "https://hnrss.org/frontpage"
    category: "tech"
    fetch_interval_minutes: 60

  - name: "arXiv CS.AI"
    url: "https://arxiv.org/rss/cs.AI"
    category: "academic"
    fetch_interval_minutes: 120
```

**输出字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 唯一标识 |
| url | str | 原始链接 |
| title | str | 文章标题 |
| summary | str | 文章摘要（最多 500 字） |
| content | Text | 完整正文（如通过 Jina Reader 获取到） |
| source_name | str | 来源名称 |
| source_category | str | 来源分类（news/tech/academic） |
| published_at | datetime | 发布时间 |
| fetched_at | datetime | 抓取时间 |
| tags | list[str] | 自动提取的标签 |
| embedding | Vector | 用于去重计算的向量 |

**边界处理：**
- RSS 解析失败 → 记录错误日志，跳过该源，继续其他源
- 网络超时 → 重试 3 次，间隔 5 秒，仍失败则跳过
- 内容为空 → 跳过该条目

### 2.4 去重算法

**策略：**

1. **URL 精确去重** — 用 Redis Set 存储已处理 URL，O(1) 查询
2. **Title 相似度去重** — TF-IDF 提取关键词，余弦相似度 > 0.85 视为重复
3. **时间衰减去重** — 同一话题 24 小时内保留热度最高的来源

**实现：**

```python
def is_duplicate(new_item: RawContent, threshold: float = 0.85) -> bool:
    # 1. URL 精确匹配
    if redis.exists(f"url:{new_item.url}"):
        return True

    # 2. Title 相似度
    new_embedding = embed(new_item.title)
    similar = vector_store.search(
        collection="raw_content",
        query_vector=new_embedding,
        top_k=5,
        filter={"source_category": new_item.source_category}
    )
    if similar and similar[0].score >= threshold:
        return True

    return False
```

## 3. 选题筛选模块（Curator）

### 3.1 热度评分模型

**公式：**

```
hot_score = (
    social_mentions * 0.5 +
    news_coverage * 0.3 +
    search_volume * 0.2
) / max_reference_value * 100
```

| 维度 | 数据来源 | 归一化方式 |
|------|---------|-----------|
| social_mentions | 微博转发/知乎回答数/GitHub stars | Log 归一化 |
| news_coverage | 24小时内新闻源数量 | 线性归一化 |
| search_volume | 百度指数/Google Trends | 相对排名归一化 |

### 3.2 受众匹配度

**方法：** 基于博主历史选题，使用 sentence-transformers 生成向量，余弦相似度计算。

```python
def calculate_audience_match(
    topic: RawContent,
    author: Author
) -> float:
    topic_vector = embed(topic.title + " " + topic.summary)
    author_vector = author.style_config["topic_vector"]

    similarity = cosine_similarity(topic_vector, author_vector)
    return similarity * 100  # 转换为 0-100 分
```

### 3.3 时效性评分

**模型：** 指数衰减

```
timeliness_score = 100 * exp(-elapsed_hours / half_life)
# 半衰期 = 6 小时
```

### 3.4 原创空间评估

**方法：** 通过 Google 搜索（模拟）检测相似内容数量。

```
originality_score = 100 / (1 + similar_count)
```

### 3.5 选题推荐输出

**每日推荐数量：** 5-10 条

**推送时机：** 每天 08:00（可根据博主习惯调整）

**输出格式：** 人工可读的 Markdown 清单，通过微信/邮件/飞书推送。

## 4. 内容创作模块（Writer）

### 4.1 文章类型与字数规范

| 类型 | 字数范围 | 结构特点 |
|------|---------|---------|
| 热点速递 | 800-1200 字 | 快、准、短，附数据图表 |
| 产品评测 | 2000-3000 字 | 深度体验、优缺点、对比 |
| 技术解读 | 2500-4000 字 | 原理讲解、代码示例 |
| 行业观察 | 3000-5000 字 | 数据支撑、逻辑严密 |
| 观点评论 | 1500-2500 字 | 个人见解、论据充分 |

### 4.2 写作风格配置

```yaml
style_config:
  tone: "专业但亲切"              # 亲切/专业/犀利
  avg_word_count: 2000            # 平均字数
  paragraph_style: "短段落"        # 短段落/长段落
  use_emoji: true                  # 是否使用 emoji
  sentence_style: "新媒体风格"     # 新媒体/传统媒体/学术风格
  banned_words:
    - "据悉"
    - "相关人士表示"
  must_include:
    - 数据来源标注
    - 结尾 CTA
```

### 4.3 Prompt 策略

**系统 Prompt（注入风格）：**

```
你是一位资深科技博主，有10年科技内容创作经验。
你的写作风格：
- 语言亲切但专业，善于用比喻解释复杂概念
- 段落短小精悍，每段不超过3句话
- 善用小标题和列表增强可读性
- 注重数据引用，标注来源
- 文章结尾有明确的行动号召（CTA）

请根据以下选题信息，写一篇微信公众号文章。
```

**用户 Prompt（注入内容）：**

```

- 核心角度：{suggested_angle}

## 要求
- 字数：{word_count_target} 字
- 生成 3 个候选标题，各自附选择理由
- 输出 Markdown 格式
- 包含配图位置建议
```

## 5. 质量审核模块（Reviewer）

### 5.1 事实核查

**检查项：**

| 检查内容 | 实现方式 | 可信度阈值 |
|---------|---------|-----------|
| 数据准确性 | 与权威来源交叉验证 | 100% 必须准确 |
| 引用可靠性 | 检查原文链接是否存在 | > 80% 链接有效 |
| 时间准确性 | 事件时间线逻辑检查 | 无逻辑矛盾 |
| 名称准确性 | 人物/公司/产品名称核实 | 100% 必须准确 |

**处理流程：**

```
发现可疑数据
    │
    ▼
标记为 [待核实]
    │
    ▼
生成核实建议（如：建议联系原文确认）
    │
    ▼
推送人工复核
    │
    ▼
人工确认后更新内容
```

### 5.2 敏感词过滤

**词库分类：**

| 类别 | 示例 | 处理方式 |
|------|------|---------|
| 政治敏感 | 涉及政治人物的负面描述 | 删除 + 替换为"相关方" |
| 色情暴力 | 低俗内容 | 删除 |
| 品牌风险 | 竞品负面描述 | 改为中性措辞 |
| 平台违规 | 微信禁止词 | 自动替换 |

**敏感词处理示例：**

```python
SENSITIVE_RULES = {
    "政治人物": r"(.*)替换为(.*)",
    "竞品负面": lambda text: text.replace("垃圾", "体验有待提升"),
    "绝对化用语": ["第一", "最好", "绝对"],
}
```

### 5.3 质量评分

```python
quality_score = {
    "facts_accuracy": 0.25,    # 事实准确性 × 25%
    "readability": 0.20,      # 可读性 × 20%
    "structure": 0.20,        # 结构完整性 × 20%
    "originality": 0.20,      # 原创度 × 20%
    "seo": 0.15,              # SEO 友好度 × 15%
}

total = sum(score[key] * weight[key] for key in weight)
# total: 0-100 分
```

**发布阈值：** 总分 ≥ 70 分可发布，< 70 分需人工确认。

## 6. 发布分发模块（Publisher）

### 6.1 发布流程

```
人工选择发布平台
    │
    ▼
格式转换（Markdown → 平台格式）
    │
    ▼
生成预览（HTML）
    │
    ▼
人工二次确认
    │
    ▼
执行发布
    │
    ▼
记录发布日志
    │
    ▼
推送发布结果通知
```

### 6.2 微信公众号格式规范

- 标题：不超过 64 字
- 封面图：16:9 比例，建议尺寸 900×383
- 正文：HTML，CSS 仅限内联样式
- 禁止：外链（非官方域名）、诱导关注/分享文案
- 摘要：最多 120 字

## 7. CLI 命令

### 7.1 日常操作

```bash
# 收集今日信息
agentnews collect

# 生成选题推荐

# 生成文章初稿

agentnews review --article-id <uuid>

agentnews publish --article-id <uuid> --platform wechat

agentnews run --task daily
```

```bash

agentnews source list

# 设置定时任务
```

### 8.1 每日统计指标

| 指标 | 描述 | 计算方式 |
|------|------|---------|
| 收集条目数 | 今日收集的原始内容数 | COUNT(raw_content) WHERE fetched_at = today |
